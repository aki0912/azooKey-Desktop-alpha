# 07. プライバシー・ライセンス・配布

## 1. 入力情報の取り扱い

ローカル推論であっても入力履歴の保存は別のリスクである。自動モードは新規のネットワーク通信、キーストロークの永続化、クリップボード読出し、全文の文脈取得を追加しない。

標準ログには文字数・処理時間・失敗理由コードなどの集計だけを出し、raw、候補、周辺文脈、URL、メール、token文字列を出さない。短いrawのハッシュも辞書攻撃で照合できるため、入力ハッシュを無条件に安全なtelemetryとして扱わない。

デバッグ用テキストtraceは初期実装でOFFとし、同梱自作fixtureのみをreplayする。実入力を学習へ取り込む仕組みは対象外。利用者が明示的に登録する単語辞書は既存の管理UI／消去方法に従う。

既存のAI変換等と、自動混在パイプラインを分離する。自動判定・fallback・再試行が既存AIのHTTP要求やプロンプト送信を暗黙に起動しないことを検査する。

## 2. セキュア入力と権限

OSが入力をIMEへ渡さないセキュア欄は、そのままOSの保護を尊重する。パスワード入力を捕捉するためのイベントtapやアクセシビリティ権限を追加しない。

任意のアプリの任意の欄が「秘密情報欄」と完全に検出できるとは仮定しない。確認できない環境ではautomaticMixedの対応範囲を狭める。Terminalやコード編集用途は必要に応じてmanualで使う。OS/APIで観測できる情報、確認した挙動、制限を文書化する。

forkのテレメトリやcrash reportに入力が含まれないか、上流のログ経路も確認する。「端末内処理だから秘密情報を記録してよい」という設計にしない。

| Zenzai v3.2 small GGUF | 公開ページにApache-2.0表示 [S11] | 固定revisionのLICENSE/NOTICE、同梱ファイルを確認 |

| 自作LR重み | これから学習する新しいartifact | データ由来・契約・配布権限の確認 |
| 英語保護語彙・学習コーパス | 特定の外部語彙を採用していない | 利用する場合にライセンスと取得条件を確認 |

上流コードのMITだけでモデル・辞書・学習コーパスを全部同じ条件で配布できると判断しない。これは配布チェックリストであり個別契約の法的結論ではない。

## 4. モデルのロードと更新

production LRは署名されたアプリbundleへ同梱する。schema/feature version、positive label、サイズ上限、finite値、SHA、語彙重複を検証する。未知versionでは自動モードを開始しない。

任意のファイルからpickle/joblibをロードする機能をIMEへ入れない。Python学習用artifactとSwift配布JSONを分離する。配布時にPython実行環境・sklearnを必要としない。

モデルhot update、自動ダウンロード、実入力によるオンライン係数更新は初期版の対象外。これらを追加する場合は署名検証、更新失敗時rollback、データ消去、設定同意を別設計する。

## 5. フォークと隔離

forkのBundle ID、Input Source ID、Mach service、LaunchAgent label、AppGroup／Application Supportパスを整合させる。文字列を全ファイルで無差別置換せず、用途別に確認して変更する。

元のazooKey設定やユーザー辞書を自動コピー・上書きしない。明示的移行機能は別タスクとし、バックアップと互換性検証を付ける。開発中は独立した表示名とデータ領域を使う。

署名のTeam IDは開発者が用意する。証明書・秘密鍵・Appleアカウント情報を仕様書やリポジトリへ書かない。配布先に応じて必要な署名・公証条件をその時点のApple資料で確認する。

## 6. 戻し方

manual設定へ戻す → OSの入力ソースを元のIMEへ切替 → 自forkだけを終了／解除 → 自forkのアプリと必要な登録だけを削除、の順を案内する。コマンドは最終的なfork識別子を確認後に作り、一般的なazooKey全削除コマンドを配布しない。

「使っている入力方式が壊れる」ことは重大な障害なので、インストール前に別の正常な入力ソースが使えることを利用者が確認する。既存のIMEに代わって勝手に有効化しない。

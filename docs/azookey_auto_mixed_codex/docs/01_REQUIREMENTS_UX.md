# 01. 要件とユーザー操作

## 1. 製品目標

macOSの入力ソースを日英のたびに切り替えずに文章を入力する。英語は入力時の大文字小文字・空白・記号を保ち、ローマ字日本語はかな漢字変換する。日英判定は独自の軽量ローカルモデル、日本語変換は既存Zenzaiの役割とする。

例は**希望する動作**であり、現行モデルが実際に出力した結果ではない。

| 入力 | 希望する表示例 | 備考 |
|---|---|---|
| `kyouhaSwiftdeAPIwotataku` | `今日はSwiftでAPIを叩く` | 空白なしで複数回切り替わる |
| `Hello world` | `Hello world` | 英語をかなへ変えない |
| `ashita meeting desu` | `明日 meeting です` | 入力した2個の空白を維持 |
| `このAPIwotukau` | `このAPIを使う` | 既存日本語はliteral、後半だけ変換 |
| `https://example.com/a?q=1` | 同一文字列 | URLを保護 |
| `made` | 文脈不足なら `made`。`I ` と `明日` などの先行文脈が取得可能なら、評価済みモデルと閾値で判定 | 綴りだけでは意図が曖昧。これは目標仕様であり実測出力ではない |

日本語候補の漢字表記はZenzai・辞書・文脈で変わる。上記の完全一致はモックを使う結合テストで固定し、実Zenzai評価では候補集合・読み・利用者意図を別に評価する。

## 2. モード

既存の `InputLanguage.japanese / english` はOS入力モードのため維持する。新しい独立設定 `CompositionPolicy.manual / automaticMixed` を設ける。

- manual：既存の操作・表示・変換挙動を維持する。
- automaticMixed：日本語入力ソースの内部で混在バッファを扱う。
- 英数キー等で明示的に英語入力ソースへ切り替えた場合：automaticMixedを休止し、従来の直接入力へ戻る。
- かなキーで日本語入力ソースに戻った場合：設定がautomaticMixedなら再開する。

初期値はmanual。自動混在入力は実験的な明示オプトインとする。「切替不要」は自動モードを有効化した後の文章内切替を指し、緊急退避用の手動切替を廃止しない。

## 3. 初回リリースの対象

標準ローマ字テーブルでの入力、英単語と日本語の交互出現、空白なし境界、ASCIIの大文字小文字、基本句読点、URL・メール・コード識別子、未完ローマ字、Backspace、候補選択、区間単位の原文／日本語指定を対象にする。

AZIK・かな入力・任意のカスタム入力表は初回automaticMixedの対象外。選択中の入力表を判別し、非対応ならmanualへ退避して設定画面へ理由を表示する。既存機能自体を削除しない。入力表を黙って標準ローマ字に置換しない。

翻訳、英語校正、英文の自動大文字化、誤字自動修正、LLMによる文意書換え、全画面キーロギング、クリップボード監視は対象外。Zenzaiの再学習も初期要件ではない。

## 4. キー操作契約：automaticMixed

| 入力・操作 | 未確定入力あり | 未確定入力なし |
|---|---|---|
| 通常文字 | 原文バッファへ挿入し再推定 | バッファ開始 |
| Space | U+0020を1個挿入。候補選択・確定には使わない | 通常の空白入力 |
| Tab | 候補を開く。開いていれば次候補 | 同期的にアプリへ渡す |
| Shift+Tab | 候補を開いていれば前候補。閉じていれば開く | アプリへ渡す |
| Enter | 候補表示中：選択を区間内で採用。閉じている：全体確定 | アプリへ渡す |
| Escape | 候補を閉じる。閉じていたら全体を原文表示へ戻す | アプリへ渡す |
| Backspace | カーソル直前の原文1書記素を削除 | アプリへ渡す |
| 左右矢印 | 下記の原文編集規則 | アプリへ渡す |
| Commandショートカット | 既存の同期ルーターの所有権を維持 | アプリへ渡す |
| 英数・かなキー | 既存の明示切替。混在バッファの確定を順序制御 | 既存どおり |

候補を採用したEnterは、部分的なOS挿入を行わない。混在バッファ全体を確定するEnterをもう一度押す。確定用Enterは改行やチャット送信として再送しない。確定後のEnterがアプリ側の改行／送信になる。

英語のみのバッファでもmarked textとして保持するため、直接英字入力とは挙動が異なる。全英語バッファでTabを押すと、原文保持と「この区間を日本語にする」を含む候補UIを開く。Tabでフォーカス移動したい場合は先にEnterで確定する。この制約を設定説明に書く。

IME応答待ちがある場合は「未確定入力なし」という古いクライアント状態を信用しない。既存のイベントルーターと追加状態を使い、キーの所有権を同期的に判断する。サーバーへ渡してconsumeしたキーを、後から `handled=false` にしてアプリへ返せたことにしない。[S3][S4]

### 4.1 Spaceの設計判断

日本語ではSpaceを変換キー、英語では空白キーにする方式には、判定が変わると同じキーの意味まで変わる問題がある。初期版は**Space常時literal、Tabで候補**に固定する。

単語区切りの便宜上打った空白を後から削除する機能は実装しない。Smart Spaceは将来の別オプションであり、この仕様のMVPにも本リリース必須機能にも含めない。学習データを作る段階でもSpaceを勝手に削除しない。

### 4.2 句読点・数字

2026-09-24の利用者要望により、Mixedの自動モードでは `- . , [ ]` の表示・確定を `ー 。 、 「 」` にする日本語優先規則を追加する。未確定バッファはASCII原文を保ち、Escapeでは原文表示・原文確定へ戻せる。英語と判定されたraw区間の直後、およびその直後の連続するASCII記号は半角を保つ。空白・日本語を挟むと日本語優先へ戻る。対応する閉じ括弧は開き括弧に合わせ、`[apple]` は `「apple」`、`apple[asita]` は `apple[明日]` とする。

確定後に記号だけを入力する場合は、既存経路で取得できた短い左文脈の末尾を参照する。取得不可なら日本語を優先する。文脈は記録しない。URL・メール・パス・ファイル名・コード識別子など既存の保護tokenと、数値に接する記号（小数、桁区切り、負号、添字、入力途中を含む）は原文を維持する。全角句読点や既存日本語・絵文字は変更しない。対象外のASCII記号・Space・manualモードも従来どおり。T0〜T2の既定engine／rendererは原文保持のままにし、この表示規則は試用runtimeとplaygroundだけで明示的に有効にする。

## 5. 区間修正と曖昧さ

候補UIに「自動」「この区間を原文のまま」「この区間を日本語として変換」を設ける。メニューからの操作を必須とし、追加ショートカットは利用者設定で割り当てる。既存F6/F10等の操作を無断で変更しない。

`made`、`no`、`to`、`name`などは英語と日本語ローマ字の両方に解釈できる。ラベルは入力者の意図であり、辞書掲載の有無だけで一意に決まるものではない。綴りによる無条件保留はせず、文脈が得られる場合は学習した判定を使い、根拠不足なら保留する。短語を必ず自動変換する要件にしない。09章参照。

ユーザー指定は同一原文区間に対して推定より優先する。編集が区間と交差した場合はそのロックを解除する。ロックを全ユーザーの恒久的言語ルールに直結しない。最初はセッション内だけに保持し、個人辞書への登録は別の明示操作とする。

## 6. 入力途中

`k → ky → kyo → kyou`、`n`、`nn`、`kan'i`、促音・拗音をイベント列で扱う。未完の子音を捨てない。変換可能部分と未完suffixを分離し、suffixは原文のままmarked text末尾に残す。

確定時の `n` / `nn` の扱いは、固定した依存Converterと標準入力テーブルで確認する。独自の正規表現で「nなら常にん」に置換しない。ローマ字解釈をコンバーターと日英推定器で二重実装しない。[S5][S8]

## 7. カーソル・編集

原文のUnicode scalar範囲、原文の書記素境界、表示文字列のUTF-16範囲を別管理する。漢字1文字をローマ字何文字に戻すかを文字数比例で推測しない。

初期の変換済み区間は表示上atomicとして扱う。左右移動で変換区間内部の編集が必要になったら、その区間を原文表示に展開してから原文書記素単位で1回移動する。他の区間は維持する。Backspaceも同じ原文上で処理する。

候補UIの区間選択は明示的な操作とし、アプリ本文内の任意クリック位置を常に正確なローマ字境界へ復元できるとは約束しない。アプリ側がcompositionを確定／取消する場合は、そのライフサイクルに従う。外部の選択範囲変更後、古い範囲を使って本文を置換しない。

## 8. 長文・外部入力

原文バッファの初期上限は256 Unicode scalars。上限を超える挿入の直前に、それまでのバッファを表示中の内容で一度確定し、新しいバッファを開始する。原文保留区間は原文のまま確定する。この容量境界での自動確定はUI仕様として明記する。確信度だけによる任意の早期確定は禁止する。

貼付け操作を監視・書換えしない。IMEに既に確定した文字列として渡されたテキスト、サービス入力、音声入力は再ローマ字化しない。Optionによるアクセント入力、dead key、JIS/USキーボード、外部キーボードは回帰テスト対象。判別できない経路では安全なliteral処理またはmanualへの退避を行う。

## 9. 安全な失敗

未学習・モデル破損：automaticMixedを開始せずmanualを継続する。

稼働中の区間推定・Zenzai失敗：現在バッファの原文を残す。空文字への置換、勝手な再入力、未知文字の削除をしない。

新規入力のローカル処理と、開発に使用するCodexの通信は別の話である。利用者の実入力をCodexや外部APIへ送信する機能は作らない。

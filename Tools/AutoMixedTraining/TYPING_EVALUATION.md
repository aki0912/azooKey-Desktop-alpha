# 入力途中の評価と英単語抽出の比較

2026-09-25。モデルを再学習せず、英単語候補の端をViterbiのRAW runに限定する処理を変更した。辞書完全一致、現在の英語スコア、前後の日本語のスコアと標準ローマ字表による妥当性は引き続き必要。候補は最長32文字、一つの保護後区間から最長の1語を採用する。区間全体が辞書にある場合はその全体判定を優先する。

この変更は、`asitahameetingg` のmeetingと最後のgが一つのRAW runになっても、meetingを照合できるようにするためのもの。語別の例外、採用閾値の緩和、履歴の表示固定は追加していない。複数の埋込み英単語を同時に最適化する処理は未実装。

## 開発データ100原文での比較

930原文のsealed datasetからdev原文100件だけを使った。変更前はHEAD `362fa25b9dc66f5df4e096ced74bffda1747d2db` のsegmenterをテストモジュールへ独立して読み込み、同じSwift評価器で比較した。元文分割、モデル係数・校正・閾値、辞書は固定。学習用データやtestをこの評価へ混ぜていない。

元文ごとに書記素単位の追加、末尾削除、全prefixを新規入力する貼り付け相当の判定を行う。1構成あたり追加2,708・削除2,608・貼り付け2,708、計8,024 snapshot（空入力を含む）。100原文×4構成で32,096 snapshotだが、独立した32,096件の精度試験ではない。

| モデル／処理 | 完成した英語spanの日本語化・追加時 | JA recall・追加時 | JA precision・追加時 | segment時間p95 |
|---|---:|---:|---:|---:|
| 現行700原文モデル・変更前 | 229 / 2,596（8.82%） | 95.71% | 94.24% | 36.946 ms |
| 現行700原文モデル・変更後 | 162 / 2,596（6.24%） | 97.01% | 94.96% | 37.073 ms |
| 再学習930原文候補・変更前 | 193 / 2,596（7.43%） | 95.66% | 94.67% | 40.764 ms |
| 再学習930原文候補・変更後 | 139 / 2,596（5.35%） | 96.36% | 95.47% | 42.102 ms |

英語spanは正解の綴りが入力され終わった後の各snapshotを露出として数える。同じ語が何度も現れる相関した観測であり、2,596個の独立した英単語ではない。JAは漢字変換区間と読み表示を合わせて数える。途中入力に対する元文の意図ラベルを使うため、短い入力だけで意図が一意に分かるという主張もしない。

削除時の日本語化も現行モデル216/2,441→154/2,441、候補183/2,441→132/2,441へ減った。追加時の既存位置のkind変化は1,010→953、候補980→924。追加と貼り付けのspan差は現行7件・候補3件、追加と削除の差は現行8件・候補6件で前後不変。既存の英語hysteresisを含むため、差0を無条件の合格基準にはしていない。

処理時間はこのMacのDebugビルドで1回ずつ測ったsegment呼出しだけの値。候補で約1.34 ms増えており、IME全体の入力応答時間や性能目標への合格を意味しない。別の実Zenzai試験では、新旧モデルともmeetingの逐次追加・削除・全体入力での保持を確認した。新候補の句点入力による「教えて」の保持も成功した。これらは固定例の人工回帰で、一般corpusの漢字表記の精度試験ではない。

結果は `build/auto-mixed/embedded-prefix-20260925/{before,after}-{old,new}-typing.json`。モデルSHA・dataset SHA・実装SHA・ログ位置を含み、本文・文脈をreportに残していない。独立testの評価・再学習・新閾値の選定は行っていない。

## 次回以降の実行

```sh
PYTHONDONTWRITEBYTECODE=1 build/auto-mixed/training-env/bin/python \
  Tools/AutoMixedTraining/pipeline.py evaluate-typing \
  --model build/auto-mixed/punctuation-930-20260924/export/model.json \
  --data build/auto-mixed/punctuation-930-20260924/dataset.json \
  --output build/auto-mixed/new-typing-dev.json
```

出力先は未作成のファイルを指定する。学習済みv2 exportとapproved datasetが必要。CLIはdev原文を固定して選び、`--test` や任意splitを受け付けない。`train_punctuation.py` にも同じ評価を組み込み、export後に `typing_dev.json` と実測時間を残す。閾値の自動順位付けは変更せず、候補レビューの資料として使う。`release_ready=false` は維持する。

Swift側で特徴量・保護・ローマ字妥当性・辞書・日本語優先・hysteresisを実行する。Corpus処理中は依存のDebug出力も抑制し、終了時に一時要求・応答を削除する。確定済み文脈は既存の人工レコード由来であり、アプリの本文や入力履歴を取得しない。

IMEへの反映・実機打鍵・長時間運用・独立testの品質測定は未実施。データ増強で入力途中の学習重みが薄まる問題も、今回学習重みを変更していないため残る。
